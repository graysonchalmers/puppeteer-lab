- Continuing from Task 2 (worker/fallback serialization), plan `docs/superpowers/plans/2026-09-16-item6-schema-v3-blender-importer.md`. New `tools/blender_import_recording.py`: a single `bpy` module, JSON-parsing/math kept in plain functions with no `bpy` dependency (importable and runnable outside Blender for a static check), the scene-building half behind `if bpy is not None`. Builds `Hand.R`/`Hand.L` root Empties with 21 keyframed child Empties each, a `Face` Empty with per-blendshape custom properties when any frame carries real face data, an optional (off by default) set of raw face-landmark Empties, an audio Sound strip when `envelope.audio` is present, and a `PuppeteerLab.AxisTriad` Empty at the origin. Axis remap Y-up (app) to Z-up (Blender): `(x, y, z) -> (x, -z, y)`.
- One deviation from the design brief's literal step 5, recorded in the script's own comment: face-Empty creation is gated on scanning frames for real blendshape data, not on `envelope.channels.includes('face')`. A literal `buildEnvelope()` output (given in the Task 3 brief) showed a `"hands"`-channel recording can still carry real face data per frame, since `mapFrameFace()` runs unconditionally regardless of `TrackingType` -- trusting `channels` alone would have silently dropped legitimate face data on a hands-channel recording.
